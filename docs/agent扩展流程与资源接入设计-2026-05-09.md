# Agent 扩展流程与资源接入设计 - 2026-05-09

## 1. 目标

本文档说明 K12 教育工作流中，具体业务 Agent 的扩展流程、开发步骤、本地资源接入方式，以及如何将其他项目接口沉淀为可复用 Skill。

适用对象：

- `TeachingDesignAgent`
- `HomeworkAgent`
- `StudentTutorAgent`
- `LearningAnalyticsAgent`
- `SafetyGuardAgent`
- 后续新增业务 Agent

推荐整体结构：

```text
Workflow Node
-> Business Agent
   -> Resource Service / Repository
      -> PostgreSQL / Vector DB / Redis
   -> Skill Service
      -> 其他项目接口
   -> LLM Client
-> AgentResult
-> SafetyGuardAgent
-> FinalizeOutput
```

## 2. Agent 职责边界

### 2.1 Agent 负责什么

业务 Agent 负责业务编排，不直接承担所有细节。

Agent 应负责：

- 理解当前工作流状态 `WorkflowState`
- 判断需要哪些资源
- 调用资源服务获取数据
- 调用 Skill 获取外部能力
- 组装 Prompt 或业务模板
- 调用 LLM 或规则生成结果
- 返回标准化 `AgentResult`

### 2.2 Agent 不建议直接做什么

Agent 不建议直接：

- 在方法里硬编码数据库 SQL
- 在方法里硬编码其他项目接口 URL
- 在方法里直接操作 Redis key
- 在方法里写复杂数据清洗逻辑
- 在方法里耦合具体 LLM 厂商 SDK

这些能力应下沉到：

```text
src/tools/
src/services/
src/repositories/
src/skills/
src/llm.py
```

## 4. 本地资源接入方式

本地资源不建议直接从 Agent 读取文件或直接拼 SQL，推荐统一通过数据库和资源服务读取。

### 4.1 PostgreSQL

PostgreSQL 适合存储结构化教育业务数据。

适合存储：

- 教材目录
- 课程标准
- 知识点体系
- 题库元数据
- 学生基础信息
- 班级信息
- 作业记录
- 考试成绩
- 错题记录
- 教案模板索引

示例表：

```text
curriculum_standards
textbook_chapters
knowledge_points
question_bank
student_profiles
class_profiles
homework_records
exam_records
wrong_question_records
lesson_plan_templates
```

推荐访问方式：

```text
Agent
-> Service
-> Repository
-> PostgreSQL
```

示例：

```text
TeachingDesignAgent
-> CurriculumService.get_standard(grade, subject, topic)
-> TextbookService.get_chapter(grade, subject, topic)
-> LessonPlanService.get_template(subject)
```

### 4.2 向量数据库

向量数据库适合做语义检索和 RAG。

适合存储：

- 教材正文切片
- 历史优秀教案
- 课件文本
- 教研资料
- 教师经验案例
- 题目解析
- 学生错题解析
- 心理/家校沟通话术库

可选向量数据库：

```text
Milvus
Qdrant
Weaviate
pgvector
Elasticsearch vector
```

推荐访问方式：

```text
Agent
-> ResourceService.search_related_resources(query, filters)
-> VectorRepository.search(query_embedding, filters)
-> Vector DB
```

示例：

```text
TeachingDesignAgent
-> 根据 grade + subject + topic 检索相似教案、教材片段、教学活动案例
-> 将检索结果放入 Prompt 上下文
-> 调用 LLM 生成教学设计
```

### 4.3 Redis

Redis 适合存储高频、短生命周期、低延迟数据。

适合存储：

- 用户会话上下文
- 多轮澄清状态
- 意图识别缓存
- 热门知识点缓存
- 最近检索结果缓存
- LLM 响应缓存
- 限流计数
- 临时任务状态

推荐 key 设计：

```text
session:{user_id}:{session_id}
intent_cache:{hash(raw_input)}
resource_cache:{grade}:{subject}:{topic}
rate_limit:{user_id}
workflow_task:{task_id}
```

推荐访问方式：

```text
Agent / Node
-> CacheService
-> RedisRepository
-> Redis
```

## 5. 其他项目接口沉淀为 Skill

如果需要调用其他项目能力，不建议让 Agent 直接请求外部接口。

推荐将外部项目接口沉淀为 Skill。

### 5.1 Skill 的定位

Skill 是对外部系统能力的稳定封装。

例如：

```text
用户中心接口 -> SchoolUserSkill
作业平台接口 -> HomeworkPlatformSkill
考试系统接口 -> ExamSystemSkill
消息通知接口 -> NotificationSkill
资源平台接口 -> ResourcePlatformSkill
```

Agent 调用 Skill，而不是直接调用其他项目接口。

```text
Agent
-> Skill
-> 外部项目 API
```

### 5.2 Skill 应封装什么

Skill 应封装：

- 接口 URL
- 鉴权方式
- 请求参数转换
- 响应数据清洗
- 异常处理
- 超时与重试
- 业务错误码映射
- 日志与追踪信息

### 5.3 Skill 不应封装什么

Skill 不应封装：

- 复杂业务决策
- Agent Prompt
- 工作流路由逻辑
- LLM 生成逻辑

这些仍应保留在 Agent 或 Workflow Node 中。

### 5.4 Skill 示例设计

```python
class ExamSystemSkill(BaseSkill):
    def get_exam_records(
        self,
        class_id: str,
        subject: str,
        date_range: tuple[str, str],
    ) -> list[dict]:
        """获取考试成绩记录。"""
        ...
```

调用链：

```text
LearningAnalyticsAgent
-> ExamSystemSkill.get_exam_records(...)
-> LearningAnalyticsService.analyze(...)
-> LLMClient.generate(...)
```

## 6. Agent 扩展标准流程

新增或增强一个业务 Agent，建议按以下步骤执行。

### Step 1：定义业务边界

明确 Agent 解决什么问题。

示例：

```text
TeachingDesignAgent：根据年级、学科、主题、课程标准和教材内容，生成教学设计。
```

需要明确：

- 面向角色：教师 / 学生 / 家长 / 教务
- 输入字段
- 输出结构
- 是否需要资源检索
- 是否需要外部接口
- 是否需要 LLM
- 安全边界

### Step 2：定义输入输出契约

建议每个 Agent 都使用统一输入输出：

```text
输入：WorkflowState
输出：AgentResult
```

`AgentResult` 建议包含：

```text
output: str
metadata: dict
```

复杂 Agent 可在 `metadata` 中返回：

```text
resources_used
skills_called
confidence
warnings
next_actions
```

### Step 3：定义资源需求

判断该 Agent 需要哪些资源。

例如 `TeachingDesignAgent`：

```text
PostgreSQL:
- curriculum_standards
- textbook_chapters
- lesson_plan_templates

Vector DB:
- similar_lesson_plans
- teaching_activity_cases
- textbook_chunks

Redis:
- resource_cache
- session_context
```

### Step 4：定义 Skill 需求

判断是否需要调用其他项目。

例如：

```text
TeachingDesignAgent:
- ResourcePlatformSkill：查询校本资源
- SchoolUserSkill：获取教师任教学段和学科

LearningAnalyticsAgent:
- ExamSystemSkill：获取考试成绩
- HomeworkPlatformSkill：获取作业完成情况
- StudentProfileSkill：获取学生画像
```

### Step 5：实现 Repository

Repository 负责和具体数据源交互。

示例：

```text
PostgresRepository
VectorRepository
RedisRepository
```

注意：

- Repository 不写业务决策
- Repository 只负责数据访问
- Repository 返回统一数据结构

### Step 6：实现 Service

Service 负责组织资源。

示例：

```text
CurriculumService
TextbookService
QuestionBankService
LearningAnalyticsService
```

Service 可以组合多个 Repository：

```text
CurriculumService
-> PostgresRepository
-> VectorRepository
-> RedisRepository
```

### Step 7：实现 Skill

Skill 负责封装其他项目接口。

建议每个 Skill 包含：

```text
name
description
timeout
retry_policy
auth_config
call method
response mapping
```

### Step 8：实现 Agent 编排逻辑

Agent 内部只做编排：

```text
1. 从 state 获取 grade / subject / topic / user_role
2. 调用 Service 获取本地资源
3. 调用 Skill 获取外部数据
4. 构建 Prompt
5. 调用 LLM
6. 返回 AgentResult
```

示例：

```python
class TeachingDesignAgent(BaseEducationAgent):
    def __init__(
        self,
        curriculum_service: CurriculumService,
        textbook_service: TextbookService,
        resource_skill: ResourcePlatformSkill,
        llm_client: LLMClient,
    ) -> None:
        self.curriculum_service = curriculum_service
        self.textbook_service = textbook_service
        self.resource_skill = resource_skill
        self.llm_client = llm_client

    def run(self, state: WorkflowState) -> AgentResult:
        resources = self.curriculum_service.get_resources(
            grade=state.get("grade"),
            subject=state.get("subject"),
            topic=state.get("topic"),
        )
        textbook = self.textbook_service.search_textbook_chunks(
            grade=state.get("grade"),
            subject=state.get("subject"),
            topic=state.get("topic"),
        )
        external_resources = self.resource_skill.search_resources(
            subject=state.get("subject"),
            keyword=state.get("topic"),
        )
        prompt = build_teaching_design_prompt(
            state=state,
            resources=resources,
            textbook=textbook,
            external_resources=external_resources,
        )
        output = self.llm_client.generate(prompt)
        return AgentResult(
            output=output,
            metadata={
                "resources_used": resources,
                "external_resources_used": external_resources,
            },
        )
```

### Step 9：接入 Node

Node 负责把 Agent 接入 LangGraph。

```text
teaching_design_node
-> TeachingDesignAgent.run(state)
-> 写入 current_agent / selected_agent / agent_output / results / metadata
```

### Step 10：接入安全合规

所有业务 Agent 输出必须经过：

```text
SafetyGuardAgent
```

安全检查包括：

- 未成年人不适宜内容
- 学生隐私泄露
- 侮辱性评价
- 违规考试答案
- 心理/医疗诊断越权
- 暴力、色情、违法内容

### Step 11：补充验证用例

每个 Agent 至少验证：

```text
1. 正常输入
2. 缺少关键字段
3. 模糊意图
4. 安全风险输入
5. 外部资源为空
6. 外部接口失败
7. LLM 调用失败
```

资源增强型 Agent

## 8. 推荐数据流

以 `TeachingDesignAgent` 为例：

```text
用户输入：帮我设计七年级数学一元一次方程教案

intent_classifier:
- intent = teaching_design
- grade = 七年级
- subject = 数学
- topic = 一元一次方程

teaching_design_node:
- 调用 TeachingDesignAgent

TeachingDesignAgent:
- 查询 PostgreSQL：课程标准、教材章节、教案模板
- 查询 Vector DB：相似教案、教学活动案例、教材片段
- 查询 Redis：会话上下文、历史检索缓存
- 调用 ResourcePlatformSkill：查询校本资源
- 调用 LLMClient：生成教学设计

safety_guard_node:
- 检查内容安全、隐私、表达风险

finalize_output_node:
- 根据 teacher 角色输出专业结构化结果
```

## 9. 失败处理建议

### 9.1 PostgreSQL 查询失败

处理方式：

```text
记录错误
-> 使用默认模板或缓存资源
-> metadata 标记 postgres_unavailable
```

### 9.2 向量数据库查询失败

处理方式：

```text
记录错误
-> 退化为结构化数据 + LLM 生成
-> metadata 标记 vector_search_unavailable
```

### 9.3 Redis 查询失败

处理方式：

```text
不阻断主流程
-> 跳过缓存
-> metadata 标记 cache_unavailable
```

### 9.4 其他项目 Skill 调用失败

处理方式：

```text
根据业务重要性决定：
- 强依赖：返回澄清/失败提示/转人工
- 弱依赖：降级生成，并标记 external_skill_unavailable
```

### 9.5 LLM 调用失败

处理方式：

```text
优先使用模板兜底
-> 返回可用但简化的结果
-> metadata 标记 llm_unavailable
```

- [ ] Vector DB 检索需求已定义
- [ ] Redis 缓存需求已定义
- [ ] 外部接口已封装为 Skill
- [ ] Prompt 模板已沉淀

- [ ] 已补充正常、异常、降级验证用例

## 11. 实施优先级建议

建议优先增强顺序：

1. `TeachingDesignAgent`
   - 最适合接入课程标准、教材、教案模板和校本资源
2. `HomeworkAgent`
   - 接入题库、知识点、难度标签和错题数据
3. `StudentTutorAgent`
   - 接入知识点解释、题目解析和学生历史错题
4. `LearningAnalyticsAgent`
   - 接入考试、作业、错题和学生画像接口
5. `SafetyGuardAgent`
   - 接入更完整的安全规则库和人工审核策略

## 12. 总结

后续业务 Agent 不应停留在模板拼接，应逐步演进为：

```text
模板型 Agent
-> 数据增强型 Agent
-> RAG Agent
-> RAG + Skill + LLM Agent
```

本地资源通过数据库统一访问：

```text
PostgreSQL：结构化教育数据
Vector DB：语义检索和 RAG 资源
Redis：缓存、会话和临时状态
```

其他项目接口统一沉淀为：

```text
Skill
```

最终目标是让 Agent 只负责业务编排，让数据访问、外部接口、缓存、LLM、安全能力都具备清晰边界和可替换性。
